# Private data and retention

Each installation holds one organization's permitted network data. Invited admins and editors see the same permitted operational records. Admins alone download exports or confirm person deletion; exports are private copies and should be stored in an access-controlled location outside source control.

The importer reads a bounded CSV upload in memory. It never saves the original file. Normalized preview rows are held in PostgreSQL for at most one hour of usable preview time. Expired rows are cleared on the next import operation/page visit or when an admin runs **Purge expired import previews**. This is operation-triggered cleanup, not a continuously scheduled daemon. Successful, cancelled and expired previews retain no normalized rows. Committed summaries retain numeric counts and record mappings; person deletion removes mappings to removed or redacted records and cancels every pending batch so it cannot recreate the deleted person.

There is no automatic time-based purge of actual partnership, action or outcome records. A person deletion instead removes affected private generated material and redacts personal narratives while preserving coherent nonpersonal states and dates. Minimal audit records retain actor/organization/target UUIDs, action, request UUID, numeric counts and recording time. They contain no deleted names, narrative, evidence, tokens or credentials. Next development request/server-function/browser-forwarding logging is disabled (`logging: false`) to avoid logging invitation URLs or private action arguments. HTTP failure logs contain an operational category; never add raw provider packets, uploaded rows, database error messages or request bodies to logs.

Live deletion does not erase database backups, exported downloads, screenshots, provider-side copies or previously received client responses. Set a backup rotation period and restrict access independently of the app. Apply the same private-directory exclusions to Git and Docker build contexts. The repository excludes `.private`, `.local`, `private`, uploads, exports, backups and logs; keep actual deployment files outside the checkout as well.

Before restoring a backup, review any deletion that occurred after its creation and reapply it before opening access. Keep the minimal deletion audit metadata in a separately controlled operational process if a backup restore would replace the live audit table. Do not restore an older backup into a publicly available demo. Rotate exposed credentials independently; deleting a person is not credential rotation.

Optional AI sends only the explicitly reviewed minimized packet. Provider retention follows the deployment's provider agreement/configuration and cannot be erased by this local transaction. Do not submit personal information through free-text instructions. CSV downloads neutralize formula-like leading cells, including whitespace/control prefixes, and quote cells; recipients should still treat files as private organization data.
